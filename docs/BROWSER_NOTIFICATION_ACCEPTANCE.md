# Browser and notification acceptance
The isolated browser suite starts from seeded roles with short-lived test JWTs, visits four real role portals, validates navigation and discovery at 320/390/768/1440px, exercises the checkout dialog and rejects cross-role access. It retains synthetic screenshots in CI artifacts. It does not execute real Google OAuth, real payments, screen-reader tests or physical-device scans. Run independently with EVENTPASS_TEST_BROWSER=true bash scripts/independent-acceptance.sh.
 
Set EVENTPASS_EMAIL_WALLET_ORIGIN to the approved isolated staging HTTPS origin for provider acceptance so test inboxes never link to the production wallet. Omit only when using the canonical production wallet. The outbox fingerprints the entire rendered template in addition to sender and recipient. Existing v1-fingerprinted in-flight notices cannot be retried across the v2 change; review these supervised exceptions instead of resetting fingerprints or risking duplicate mail. No provider credentials or email delivery activation included.
